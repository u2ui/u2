# U2 Issues (Gemini Review)

Findings spotted during code review that are not already tracked in `TODO.md` or `u2/plan-scoped-refactoring.md`.

## Open for discussion

- **[css/classless/variables.css:37](css/classless/variables.css#L37):** `--line-height: calc(var(--line-height-absolute) + var(--line-height-relative));` references `--line-height-absolute` and `--line-height-relative`, which are only defined by the stylers ([el/system/styler.js:250](el/system/styler.js#L250): 1.5em + .5rem, [u2/tools/variable-styler.js:27](u2/tools/variable-styler.js#L27): 1em + .5rem), making `--line-height` invalid by default when `variables.css` is loaded. Needs a decision on the default values.
- **[attr/skin/skin.css:22](attr/skin/skin.css#L22), [L30–32](attr/skin/skin.css#L30-L32), [L39](attr/skin/skin.css#L39):** Broad `:has(>&)` selectors in `[u2-skin=invert]` and `[u2-skin=theme]` may cause expensive style recalculations. `[u2-skin]:has(>&)` has a red `outline` as a dev warning ("invert can not be child of skin") – keep or remove?
- **[css/utils/utils.css:39](css/utils/utils.css#L39):** `.u2-hitBig::after` (marked "idea") has a visible tint `background:#f001;` – leftover or intended visualisation?
- **[el/carouselnav/carouselnav.js:35](el/carouselnav/carouselnav.js#L35) vs [el/carousel/carousel.js:358](el/carousel/carousel.js#L358):** Attribute name mismatch — `u2-carouselnav` looks up `sync-group`, while `u2-carousel` uses `sync`.
- **[theme/*/theme.css](theme/brutalist/theme.css#L6-L8):** Themes still define `--hsl-h`, `--hsl-s`, `--hsl-l`, but [css/classless/variables.css](css/classless/variables.css#L4-L9) no longer derives `--color` from them. Only some themes still use them for their own colors (e.g. `--hsl-s` in [theme/tech/theme.css:20](theme/tech/theme.css#L20), `--hsl-h` in [theme/soft/theme.css:20](theme/soft/theme.css#L20)) – derive `--color` again or remove the leftovers?
- **[el/system/styler.js:484](el/system/styler.js#L484), [u2/tools/dev-iframe.js:107](u2/tools/dev-iframe.js#L107):** Inline `onclick="..."` handlers in Shadow DOM markup are blocked by strict CSP without `'unsafe-inline'`.
- **[el/ico/ico.js:152](el/ico/ico.js#L152):** `cachedRequests[url]` permanently caches rejected `fetch` promises, so a transient error breaks that icon for the rest of the session. Dropping rejected promises means retrying on every render for permanently missing icons (404) – trade-off.
- **[el/tabs/tabs.js:87](el/tabs/tabs.js#L87):** `<u2-tabs selected=1>` throws on upgrade: `attributeChangedCallback` runs before `connectedCallback`, so `_selectTab()` reads `this.tabs[i]` while `this.tabs` is still undefined. Right after, `connectedCallback` overwrites `selected` with the first tab carrying `[selected]` (or 0), so the host attribute never works as the initial value. Which one should win?
- **[el/rating/rating.js:80](el/rating/rating.js#L80):** `render()` rebuilds all stars on an `icon`/`max` change and drops their `.active` classes; the current value is no longer shown until the next `value` set.
- **[el/system/styler.js:229](el/system/styler.js#L229):** The styler UI mixes German labels (`Basis Farbe`, `Typografie`, `Schatten`, `Zeilenhöhe relativ` …) with English ones (`Colors`, `Layout`, `Form Controls`, `Border Radius`). Decide on one language or translate like the other elements.
- **[el/input/input.js:271](el/input/input.js#L271):** The file type shows a hardcoded German `Durchsuchen...` button label, while other elements (pagination, tour, dialog) translate their UI texts per `lang`.
- **[el/cookiebanner/cookiebanner.js:73](el/cookiebanner/cookiebanner.js#L73):** `'ignore': null` makes a `text/plain` script with `data-cookieconsent="ignore"` log "Unknown category" and never run. With Cookiebot, `ignore` means "not blocked" – should such a script run unconditionally, or be skipped silently?
- **[el/table/tests/columns.api.html](el/table/tests/columns.api.html#L470):** "Run all tests" fails against the current `Columns`: test 6 ([L470](el/table/tests/columns.api.html#L470)) expects a colspan cell in every column it spans and throws, while `cellsByGroup()` lists a spanned cell only under its first column; test 8 ([L517](el/table/tests/columns.api.html#L517)) expects `indexOf(null) === undefined`, the code returns `-1`. The same with the code before the latest cleanup – which behaviour is the contract?
- **[js/PointerObserver/PointerObserver-no-scroll.js](js/PointerObserver/PointerObserver-no-scroll.js):** Unreferenced copy of `PointerObserver.js` without the scroll handling, already diverging (`onstart && onstart(e)` vs `?.`, active vs parked "new" block). Delete or mark `zzz`?
- **Constructors that write to the host** make `document.createElement()` throw `NotSupportedError` ("The result must not have attributes/children"): [el/buttongroup/buttongroup.js:9](el/buttongroup/buttongroup.js#L9) (`u2-focusgroup`), [el/masonry/masonry.js:6](el/masonry/masonry.js#L6) (`class`), [el/typewriter/typewriter.js:34](el/typewriter/typewriter.js#L34) (`innerHTML`), [el/system/system.js:11](el/system/system.js#L11) and [el/system/styler.js:223](el/system/styler.js#L223) (`popover`/`style`). Concrete cases for the lifecycle convention in `TODO.md`.
